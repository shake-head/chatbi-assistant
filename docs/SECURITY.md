# 安全设计

## 1. 资产与信任边界

需要保护的数据：密码哈希、JWT 密钥、模型 API Key、用户上传数据、分析结果、会话历史和 AI 成本记录。

不可信输入：上传文件、列名/单元格内容、自然语言问题、模型输出、请求头与客户端传入路径。

## 2. 主要威胁与控制

| 威胁 | 控制 |
|---|---|
| 模型生成恶意代码 | 模型只允许返回 `AnalysisPlan` JSON；后端不执行模型代码 |
| Prompt 注入 | 数据值仅作为不可信内容；执行器只接受列白名单和枚举操作 |
| 代码注入 | 不使用 `eval`、`exec`、动态 import、字符串拼接 SQL |
| 沙箱逃逸 | 独立子进程、固定代码、超时、Linux CPU/内存限制、禁用 socket/文件写入 |
| 路径穿越 | 丢弃上传文件名；UUID 存储路径；`Path.resolve()` 后强制位于 `datasets` 根目录 |
| 越权访问 | 数据集、会话、消息、用量查询全部带 `user_id`；跨用户统一返回 404 |
| 密码破解 | bcrypt；密码限制 8–72 UTF-8 字节；登录错误不区分邮箱是否存在 |
| JWT 伪造/过期 | HS256 签名、issuer、iat/exp 必需、类型校验；生产要求强密钥 |
| 资源滥用 | 上传大小/行数/列数限制、AI 限流、月度预算、分析超时、结果行列限制 |
| 模型成本失控 | 网关统一计量、预算查询、失败审计、Prometheus 成本指标 |
| 密钥泄漏 | 环境变量/SecretStr；不写入代码；容器可只读；日志不记录密钥 |
| 错误信息泄漏 | 统一错误协议；未知异常只返回通用消息，堆栈仅服务端日志 |
| 容器提权 | 非 root、只读根、capabilities 全丢弃、no-new-privileges、资源限制 |

## 3. 沙箱说明

当前沙箱的强约束是“只执行后端固定代码”，不是允许任意 Python 后做隔离。进程级控制包括：

- 最小环境变量，排除 `AI_API_KEY`、`JWT_SECRET`、`DATABASE_URL` 等。
- 输入路径必须处于受管数据集目录。
- socket 与 DNS 调用被禁用。
- `builtins.open` 禁止写/追加/独占/更新模式。
- Linux 使用 `RLIMIT_CPU` 与 `RLIMIT_AS`；所有平台有父进程超时与输出规模限制。
- 输入仅包含 JSON 计划与 schema；输出再次校验列名、行数、字符串长度、有限数值和数值范围。

Windows 没有 `resource` 模块，CPU/内存硬限制依赖容器或系统级隔离。生产建议只运行 Linux 容器。不要把该沙箱用于执行第三方插件或任意用户代码。

## 4. 数据隔离

- JWT `sub` 只保存用户 ID；每次请求重新查询用户。
- 数据集详情、重解析、删除、聊天均查询 `id + user_id`。
- 会话列表/历史/删除查询 `Conversation.user_id`。
- Chat 请求还校验 `conversation.dataset_id == dataset.id`。
- 跨用户资源统一返回 404，避免泄露资源存在性。
- AI 用量仅聚合当前用户。

## 5. 上线安全清单

- [ ] 设置随机且至少 32 字符的 `JWT_SECRET`，定期轮换并接受旧 token 失效。
- [ ] 使用 HTTPS/TLS 终止，不在日志中记录 Authorization。
- [ ] 配置生产托管模型，禁止 `AI_PROVIDER=local`。
- [ ] 设置模型输入/输出单价与用户预算。
- [ ] 保证 Redis 可用并设置网络隔离/密码。
- [ ] `/metrics` 只对内网或监控系统开放。
- [ ] 定期备份 SQLite 与 `DATA_DIR`，验证恢复。
- [ ] 限制容器内存、CPU、PID；保持根文件系统只读。
- [ ] 执行 `ruff check`、`pytest`、依赖漏洞扫描和容器镜像扫描。
- [ ] 用真实业务问题建立评测集，回归分析准确性。
- [ ] 对上传超大文件、跨用户访问、限流和预算超限做告警。

## 6. 已知限制

- bcrypt 不提供密码泄露检测或 MFA。
- 没有邮箱验证、找回密码、刷新 token、token 吊销列表。
- SQLite 单机写入并发有限，不适合多实例。
- 本地规则 AI 仅用于开发；生产质量取决于托管模型和评测。
- 结果缓存尚未启用，避免多轮上下文和权限导致错误复用。
- SSE 没有断线续传和事件 ID。
