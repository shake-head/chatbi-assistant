# 分析评测基线

## 目标

把“模型换版/提示词调整/执行器调整”与业务正确性回归解耦。评测不只检查接口是否 200，还检查分析计划、聚合结果和结论是否基于结果。

## 建议评测集结构

```json
{
  "name": "sales-baseline",
  "dataset": "sales.csv",
  "cases": [
    {
      "question": "各区域销售额合计是多少？",
      "expected": {
        "group_by": ["region"],
        "metric_column": "amount",
        "aggregation": "sum",
        "row_count": 3,
        "chart_type": "bar"
      }
    }
  ]
}
```

建议至少覆盖：

1. 单指标总和、平均值、最大值、最小值和计数。
2. 单维度分组、双维度分组、Top N 排序。
3. 等于、in、between、contains、空值过滤。
4. 日/周/月/季度/年时间粒度。
5. “近 N 个月/周/天”相对日期。
6. 占比饼图、趋势折线、无维度汇总表。
7. 空结果、未知列、非数值求和、超大结果集。
8. 多轮追问中的上下文继承。
9. Prompt 注入文本、恶意列名、超长字符串。
10. 数值/单位/货币/日期格式和空值脏数据。

## 自动验收

当前仓库中：

- `pytest` 覆盖结构化计划、沙箱、图表、结论、用户隔离、AI 降级和错误协议。
- `scripts/smoke_e2e.py` 使用临时数据完成真实 HTTP 全链路。
- `GET /account/ai-usage` 与 Prometheus 指标可观察 token 和成本。

接入真实托管模型后，需要新增独立评测脚本，调用与生产相同的 `AI Gateway`，将模型输出计划与金标准比较，并记录：

- 计划完全匹配率。
- 聚合/维度/过滤字段准确率。
- 结果数值正确率。
- 无依据结论率（应接近 0）。
- 平均延迟、token 和成本。
- 失败与降级比例。

不要把本地规则提供方的结果当作生产模型准确率；它只用于开发闭环和确定性回归。

## 发布门禁建议

| 指标 | 建议门槛 |
|---|---|
| 计划 schema 合法率 | ≥ 99% |
| 核心问题金标准通过率 | ≥ 90% |
| 结果数值正确率 | ≥ 98% |
| 无依据结论 | 0 个严重案例 |
| P95 端到端延迟 | < 10 秒 |
| AI 失败率 | < 1% |

真实阈值应根据业务问题集和模型成本调整，并保留每次评测的模型名、提示词版本、代码版本和原始输出。
