# AI 数据分析助手 · 操作手册

> 面向日常使用与运维维护。普通用户请看 `docs/USER_GUIDE.md`，本手册重点讲部署、配置、监控与故障处理。

## 1. 项目概述

这是一个基于 FastAPI 的 AI 数据分析助手（ChatBI）。用户上传 CSV / Excel 数据集，用中文自然语言提问，系统完成「结构化意图 → 受控 Pandas 计算 → 图表规格 → 结论生成」，返回图表、结果表和自然语言结论。

- 业务入口（中文操作台）：<http://127.0.0.1:8000/>
- 接口文档（开发者）：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/health>
- Prometheus 指标：<http://127.0.0.1:8000/metrics>

## 2. 技术栈与结构

- 后端：Python 3.11、FastAPI、SQLAlchemy、Redis、Alembic、Uvicorn
- 数据：SQLite（元数据）+ Parquet（数据本体）
- 前端：原生 HTML/CSS/JS + 本地 ECharts，由 FastAPI 直接托管
- 部署：Docker Compose，非 root / 只读容器

```text
app/                后端代码与前端静态资源
  ├── api/          路由、依赖、中间件、错误处理
  ├── core/         配置、JWT、限流、日志、指标
  ├── models/       数据模型
  ├── schemas/      Pydantic 模型
  ├── services/     解析、AI 网关、沙箱、图表、编排
  └── static/       中文操作台
migrations/         Alembic 迁移
scripts/            启动、停止、健康与 E2E 脚本
tests/              单元、集成、安全、前端测试
docs/               架构、安全、运维、用户文档
```

## 3. 环境要求

- Python 3.11（固定 `>=3.11,<3.12`）
- Docker 与 Docker Compose（推荐部署方式）
- Redis 7（Compose 已内置）
- 托管大模型 API（可选，OpenAI Chat Completions 兼容；未配置时开发/测试用本地规则）

## 4. 部署方式

### 4.1 Docker Compose（推荐）

```powershell
cd E:\workspace2

# 首次或代码变更后：重新构建并后台启动
docker compose up --build -d

# 仅启动（不重新构建）
docker compose up -d

# 查看状态
docker compose ps

# 停止
docker compose down

# 停止并清空数据卷（会删除数据库与上传数据，谨慎）
docker compose down -v
```

容器特性：API 以非 root 运行、根文件系统只读、`/data` 为持久化卷、`/tmp` 受限 tmpfs、丢弃全部 Linux capabilities、限制内存与 PID 数量。

### 4.2 本地开发启动

```powershell
cd E:\workspace2

py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe scripts\configure_local_env.py
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

> 注意：本地启动与 Docker 都占用 8000 端口，不要同时运行。

## 5. 配置说明

配置通过环境变量或项目根目录 `.env` 读取，完整字段见 `.env.example`。

| 变量 | 说明 |
|---|---|
| `APP_ENV` | `development` / `test` / `production` |
| `API_HOST` / `API_PORT` | 服务监听地址与端口 |
| `DATA_DIR` | 数据目录，默认 `./var` |
| `DATABASE_URL` | 默认 `sqlite:///var/chatbi.db` |
| `REDIS_URL` | 默认 `redis://localhost:6379/0` |
| `JWT_SECRET` | 生产环境必须 ≥32 位随机字符 |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 登录有效期（默认 60 分钟） |
| `MAX_UPLOAD_SIZE_MB` | 上传大小上限（默认 50MB） |
| `MAX_DATASET_ROWS` | 数据集行数上限（默认 100 万） |
| `AI_PROVIDER` | `auto` / `openai_compatible` / `local` |
| `AI_API_BASE_URL` | 兼容 API 前缀，如 `https://host/v1` |
| `AI_API_KEY` | 模型密钥 |
| `AI_MODEL` | 模型名 |
| `AI_MONTHLY_BUDGET_USD` | 月度预算上限 |

生产环境远程模型示例：

```dotenv
APP_ENV=production
AI_PROVIDER=openai_compatible
AI_API_BASE_URL=https://your-provider.example.com/v1
AI_API_KEY=your-secret
AI_MODEL=your-model-name
AI_INPUT_COST_PER_MILLION_USD=0.5
AI_OUTPUT_COST_PER_MILLION_USD=1.5
AI_MONTHLY_BUDGET_USD=20
JWT_SECRET=<至少32位随机字符串>
```

生成 JWT 密钥：

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 8. 监控与成本

- `GET /health`：进程存活检查。
- `GET /metrics`：Prometheus 指标，含 HTTP 请求量/延迟、AI 调用结果与累计估算成本。
- `GET /account/ai-usage`：当前用户本月调用数、Token、费用与剩余预算。
- 生产建议接入 Prometheus/Grafana，并对 5xx、AI 失败率、限额拦截和成本突增告警。

## 9. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 “Port 8000 is already in use” | 端口被 Docker 或旧进程占用 | 二选一运行；查 `Get-NetTCPConnection -LocalPort 8000` 后停掉占用进程 |
| 访问 `/` 返回 404 | 运行的是旧镜像，未包含前端 | `docker compose up --build -d` 重新构建 |
| 打开操作台但页面空白/脚本不加载 | `.mjs` MIME 错误或缓存 | 确认使用最新代码；强刷浏览器（Ctrl+F5） |
| `401 UNAUTHORIZED` | 未登录或登录过期 | 重新登录；Token 默认 60 分钟过期 |
| `409 DATASET_NOT_READY` | 数据仍在解析 | 等待状态变为「可分析」再提问 |
| `409 EMAIL_ALREADY_REGISTERED` | 邮箱已注册 | 换邮箱或直接登录 |
| `413 FILE_TOO_LARGE` / `DATASET_TOO_LARGE` | 文件/行数超限 | 减小文件或行数 |
| `415 UNSUPPORTED_FILE_TYPE` | 格式不支持 | 仅支持 CSV / XLSX / XLS |
| `422 EMPTY_FILE` / `DATASET_PARSE_FAILED` | 文件空或无法解析 | 换有效文件 |
| `429 RATE_LIMIT_EXCEEDED` | 请求太频繁 | 稍等再试 |
| `429 AI_QUOTA_EXCEEDED` | 月度 AI 预算用尽 | 查看用量或调整预算 |
| `503 AI_SERVICE_UNAVAILABLE` | AI 服务不可用 | 稍后重试或检查模型配置 |
| Redis 不可用 | 开发环境自动降级为进程内限流 | 生产环境必须保证 Redis 可用 |

## 10. 数据备份与恢复

- 元数据数据库：`var/chatbi.db`（Docker 卷为 `chatbi_data`）。
- 数据本体：`var/datasets/`。
- 备份：停止写入后，复制 `chatbi.db` 与 `datasets/` 目录即可。
- 恢复：还原上述文件到对应 `DATA_DIR` 后重启服务。

> 当前为单机 MVP；多实例部署前需将 SQLite 迁移到 PostgreSQL、数据本体迁移到对象存储。

## 12. 安全注意事项

1. 模型只输出经过校验的结构化分析计划，不执行模型生成的任意代码。
2. 计算在独立沙箱进程中执行：固定白名单操作、超时、内存/CPU 限制、禁网、禁文件写入。
3. 所有数据集/会话/消息查询均强制用户归属，跨用户访问统一返回 404。
4. 生产环境必须替换 `JWT_SECRET`，且拒绝本地 AI 降级路径。
5. 上传文件使用服务端 UUID 路径，阻止路径穿越。
6. 失败调用也会写入用量审计，便于追踪成本与异常。
